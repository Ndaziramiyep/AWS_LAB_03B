A.2What happens without a solution

Without an automated, reversible release process, each change is a risk to the order system. Figure 3 shows the six consequences, and each one costs Onward either orders, security, or engineering time.

no-solution.drawioPage-3
Figure 3 · Consequences of shipping without a safe delivery process
Business impact
  • Lost orders. Every minute of downtime during a release is revenue that does not come back.
  • Breach exposure. Long-lived access keys are a leading cause of cloud security incidents [8].
  • Slow change. Fear of releases leads to large, infrequent batches, which make every release riskier [1].
  • Hard to rebuild. Hand-made environments drift, so problems cannot be reproduced or recovered from quickly.

Sources: [1] Well-Architected OPS06 · [5] GitHub OIDC for AWS · [8] Well-Architected SEC02 temporary credentials.

B.1Chosen approach and architecture

ECS on Fargate in private subnets behind a single ALB. GitHub Actions (OIDC) pushes the image to ECR. EventBridge starts CodePipeline, and CodeDeploy releases it blue/green with canary traffic and alarm-based automatic rollback. All infrastructure is CloudFormation deployed by GitSync, and AWS services are reached through VPC endpoints, not a NAT gateway.

onward-architecture.drawioPage-4
Figure 4 · Target architecture and the numbered flow of one change
  1. Merge to main in the app repo. This is the only manual step.
  2. GitHub Actions tests, assumes an IAM role through OIDC (1-hour credentials, no stored keys), and pushes :<sha> and :latest to ECR.
  3. ECR emits an Image Action PUSH event.
  4. An EventBridge rule starts CodePipeline. There is no polling.
  5. The pipeline registers a new task definition and calls CodeDeploy.
  6. CodeDeploy starts the green tasks in both AZs, shifts 10% of traffic for 5 minutes, then 100%, and rolls back automatically if an alarm fires.

B.3Who benefits

The same release, before and after. The manual chain of risky steps becomes an automated chain where the only human action is approving a merge.

before-after.drawioPage-6
Figure 6 · Release process today vs with the solution
Customers

No outage during releases. A bad release reaches at most 10% of traffic, for minutes, before rollback.

CTO

Merging is the whole release process. Releases become frequent, small, and routine.

Head of Security

No keys to leak, one public door, and an application that cannot reach the internet.

Head of Operations

Self-healing tasks across two AZs, automatic scaling, and alarms watching every release.

Finance Lead

Per-second Fargate billing, scale-to-zero or teardown when idle, and a clear endpoint cost.

Engineers

Two small, documented repos, and the same environment rebuilt from code every time.

Cost in one line

About $94/month while running (eu-west-1): ~$48 interface endpoints, ~$24 ALB, ~$18 Fargate, plus small amounts for logs and alarms. Endpoints cost about $13 more than one NAT gateway, but NAT would give the app an internet path, which Security rules out. Teardown brings the idle cost to zero.
